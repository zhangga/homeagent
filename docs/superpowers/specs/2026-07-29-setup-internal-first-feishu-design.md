# HomeAgent Setup 内部优先的飞书流程设计

## 背景

当前首次设置把“发布对外共享版本”放在机器人创建与消息监听激活之间。飞书应用只有在需要加入外部群或接受外部用户私聊时才需要发布对外共享；企业内部群聊并不依赖这项能力。把它放进主流程会让用户误以为机器人创建后必须发布应用，也会延迟最常见的内部使用路径。

## 目标

首次设置采用内部使用优先的线性流程：

1. 选择并确认 AI；
2. 创建或连接飞书机器人；
3. 激活飞书消息监听；
4. 连接第一个内部群聊，或选择仅私聊使用；
5. 完成设置。

对外共享继续作为飞书连接页中的可选高级能力，保留现有发布指引、状态记录和真实外部群消息验证。

## 非目标

- 不删除或重置已有的对外共享状态。
- 不删除对外共享的开始验证、内部使用和状态查询路由。
- 不改变飞书应用权限清单、机器人创建协议或管理员审批机制。
- 不在首次设置中新增“内部使用/外部使用”选择。

## 方案比较

### 方案 A：从 Setup 状态机移除对外共享（采用）

首次设置不读取对外共享状态来决定当前步骤。飞书连接页继续展示完整的对外共享控制。

优点：

- 最常见的内部使用路径最短；
- 不写入虚假的“已跳过”偏好；
- 已有外部共享能力和数据保持独立、可继续使用。

代价：

- 需要外部群的用户要在完成设置后进入飞书连接页开启该能力。

### 方案 B：首次设置先询问内部或外部使用

优点是意图更显式；缺点是每个首次用户都会遇到一道大多数人不需要的产品决策，增加 setup 负担。

### 方案 C：创建机器人后自动标记仅内部使用

页面最少，但系统会把“尚未选择”错误地持久化为“明确跳过”，后续开启外部群时语义不清晰。

## 状态机

`SetupStep` 只包含：

```text
ai → feishu → activate → invite → done
```

判定规则：

- 当前 AI 不可用时停在 `ai`；
- Bot 身份未验证时停在 `feishu`；
- Bot 已验证但运行实例尚未使用该身份，或消费者未就绪时停在 `activate`；
- 消息监听就绪但没有已连接群聊，且 onboarding 未完成时停在 `invite`；
- 其他情况进入 `done`。

`not_started`、`awaiting_external_message`、`verified` 和 `skipped` 等对外共享状态都不得影响以上判定。

## 界面与路由

### Setup

- 步骤导航不再出现“发布对外共享”。
- 不再渲染对外共享发布或外部群消息验证页面。
- 飞书机器人创建成功后直接进入监听激活。
- 激活完成后直接进入群聊连接。

### 飞书连接页

- 保留“对外共享”区域。
- 保留打开飞书应用、开始验证、重新检查和内部使用等现有操作。
- 文案明确说明这是加入外部群和接受外部用户私聊时才需要的可选能力。

现有 `/setup/feishu/external-sharing/start` 和 `/setup/feishu/external-sharing/skip` 路由继续工作，以兼容已打开的旧页面和现有表单；新 setup 页面不再链接这些路由。

## 数据与兼容性

- 不迁移、不清除任何已有设置。
- 已验证、等待验证或已跳过的对外共享状态继续按 App ID 保存。
- 已处于旧版 `external_share` 页面时，刷新后会根据 Bot 与运行时状态进入 `activate`、`invite` 或 `done`。
- Integrations 页仍可继续或重新开始对外共享验证。

## 错误处理

- Bot 身份变更仍要求重启或激活消息监听。
- 消息消费者失败仍停留在 `activate` 并展示诊断入口。
- 对外共享配置失败只影响 Integrations 中的可选能力，不得把 onboarding 退回或阻塞在 setup。

## 测试

采用公共界面行为测试：

1. Bot 就绪但运行时未就绪时，无论对外共享状态为何，当前步骤都是 `activate`。
2. 运行时就绪且没有群聊连接时，无论对外共享状态为何，当前步骤都是 `invite`。
3. Setup 的步骤导航和页面内容不再包含“发布对外共享”。
4. Integrations 页仍展示对外共享控制，现有开始验证和内部使用路由继续可用。
5. 现有 setup 完成、重启恢复和飞书 provisioning 轮询测试继续通过。
