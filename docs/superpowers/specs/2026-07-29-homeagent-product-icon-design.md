# HomeAgent 产品图标与品牌标志设计

## 状态

设计已在 2026-07-29 的可视化评审中通过。实现尚未开始。

## 背景

HomeAgent 当前没有统一的产品图标：

- 管理后台导航使用 `🧠`；
- 首次设置页面使用 `⌁`；
- macOS App bundle 没有声明 `CFBundleIconFile`，仓库中也没有正式
  `.icns` 资源；
- 仓库没有可供飞书机器人使用的标准头像资产。

这些符号分别表达“脑”“连接”和空白系统图标，无法让用户形成稳定的
HomeAgent 品牌记忆。产品本身也已经超出通用知识工具：它长期运行在本地，
通过飞书参与家庭或小团队协作，持续记住上下文，并主动执行提醒、学习和研究
任务。因此需要一个同时表达 `Home`、`Agent` 和温度感的统一标志。

## 目标

- 建立一个能代表 HomeAgent 产品定位的核心图标，而不是通用 AI 符号。
- 在 macOS、飞书、后台导航和首次设置中使用同一套视觉语言。
- 在 16px 到 1024px、浅色和深色背景、方形和圆形裁切下保持可识别。
- 让正式资产离线可用，不依赖外部图片、字体或 CDN。
- 在构建和测试中阻止图标丢失、旧符号回流和不同触点各自重画。

## 非目标

- 不更改 `HomeAgent` 产品名、`homeagent` slug、bundle identifier、URL
  scheme、数据目录或环境变量。
- 不把品牌更新扩展成整个管理后台的视觉重构。
- 不设计拟人吉祥物，不增加眼睛、嘴巴、肢体或角色动画。
- 不把运行中、离线、告警等状态编码进品牌标志。
- 不声称当前飞书自动创建接口能够设置机器人头像。
- 不自动修改已经创建的飞书应用或机器人身份。

## 已评审的方向

最初比较了三个产品信号：

1. 家的长期记忆；
2. 家庭智能中枢；
3. 有温度的 AI 伙伴。

评审选择第三项。随后在拟人小屋、屋檐守护和抽象智能存在之间选择了
“屋檐守护”，并明确使用温暖而非绿色的配色。暖色方案选择“陶土与蜂蜜”。
核心图形在爱心、智能火种和对话回环之间选择“智能火种”。

最终概念为：

> HomeAgent 是屋檐下持续亮着的智能火种。

屋檐代表 Home、容纳与守护；中心四向星芒代表会理解、会行动的 Agent，也像
家中一直亮着的灯。陶土色提供温度与生活感，避免常见 AI 产品的冷紫蓝视觉。

## 核心标志

### 几何

完整 App Icon 使用圆角方形底板，内部由三部分组成：

1. 一条连续、端点圆润的屋顶折线；
2. 从屋顶下方延伸的开放式房屋轮廓；
3. 位于房屋视觉中心的四向火种星芒。

完整大尺寸版本在火种外增加低对比度圆形光晕，并在屋顶右上方增加一颗
固定的小火星。小火星只是品牌细节，不表示通知或运行状态，也不得动态变色。
48px 以下移除光晕与小火星。

屋檐与火种必须共同出现。不得单独用一个通用四向星作为 HomeAgent 标志，也
不得把火种替换成爱心、聊天气泡、脑或机器人头。

### 字标

界面品牌锁定使用小写 `homeagent`，采用系统可用的圆润无衬线字体栈，以
`Avenir Next`、`Segoe UI` 和通用 sans-serif 依次降级。字标不作为图片保存，
避免字体授权和清晰度问题。

正文、窗口名、系统名称和无障碍文本继续使用规范写法 `HomeAgent`。

## 色彩系统

| 角色 | 色值 | 用途 |
|---|---|---|
| 晨陶 | `#DA7B51` | 大尺寸渐变亮部 |
| 主陶土 | `#C45F43` | 标准底板、浅色背景单色 glyph |
| 深陶 | `#A94733` | 大尺寸渐变暗部 |
| 火种金 | `#F4C965` | 火种与深色背景强调 |
| 暖奶油 | `#FFF3E5` | 屋檐、深色背景前景 |
| 炉灰墨 | `#342A25` | 字标与单色深色版本 |

只有 `>=128px` 的完整图标使用从晨陶到深陶的渐变。48–127px 使用主陶土
纯色底板，避免不同渲染环境造成色带或边缘模糊。24px 以下不依赖第二颜色。

不允许页面按自身主题重新着色品牌底板。浅色背景上的独立 glyph 使用主陶土；
深色背景使用暖奶油屋檐和火种金；背景不可控时使用完整主陶土底板。

## 响应式版本

| 显示尺寸 | 版本 | 保留内容 |
|---|---|---|
| `>=128px` | 完整版 | 渐变底板、屋檐、火种、低对比光晕、小火星 |
| `48–127px` | 扁平版 | 纯色底板、屋檐、双色火种 |
| `24–47px` | 紧凑版 | 纯色底板、加粗屋檐、简化火种 |
| `16–23px` | 单色版 | 无底板、屋檐与实心火种 |

这些版本是独立导出的响应式资产，不通过把 1024px 完整版机械缩小来代替。
所有版本使用相同的屋檐比例和火种中心，不得出现视觉位置跳动。

## 资产架构

### 规范源

`assets/brand/homeagent-mark.svg` 是完整彩色标志的规范源，
`assets/brand/homeagent-glyph.svg` 是单色 glyph 的规范源。两者只能包含静态
SVG 形状、颜色和渐变，不得包含脚本、事件处理器、外部 URL、字体或嵌入图片。

`assets/brand/README.md` 记录色值、viewBox、保护区、响应式规则和生成资产清单。
所有 PNG 和 `.icns` 都是派生资产，不能成为新的几何规范源。

### Web 嵌入

Web 层新增一个共享的品牌组件，供 `layout.ts` 和 `setup-view.ts` 使用。组件从
规范 SVG 以 Bun 的 text loader 导入，并把仓库内受信任、经过静态校验的 SVG
内联到 HTML。页面不复制 path 数据，也不通过网络请求品牌资源。

组件至少支持：

- `full`：带陶土底板的完整或扁平标志；
- `dark`：深色导航上的暖奶油与火种金 glyph；
- `mono`：单色 glyph；
- 可访问名称和纯装饰两种语义。

通过明确的尺寸参数选择响应式版本，调用方不得自行用 CSS 隐藏标志的内部
元素。

### 飞书头像

`assets/brand/homeagent-feishu-avatar-512.png` 是 512×512 的方形 PNG。关键屋檐
和火种全部位于中心圆形安全区内，确保飞书圆形裁切不会截断轮廓。

飞书 Integrations/设置页面提供该 PNG 的下载入口，并说明需要在飞书应用管理
中手动上传。下载由 HomeAgent 本地页面提供，不访问外部服务。

`RuntimePaths` 增加明确的品牌资源目录：源码运行时指向仓库
`assets/brand`，打包运行时指向 `Contents/Resources/brand`。生产入口把
`homeagent-feishu-avatar-512.png` 的绝对路径注入 `WebOptions`；Web 层只通过
该受控路径读取并返回文件，不接受请求参数拼接路径。开发入口同样传入仓库
资产路径，测试则传入临时 fixture。下载路由固定，不提供任意文件读取能力。

当前 `registerApp` 适配器只传递应用名称、描述和权限/事件预设；本设计不增加
未经验证的头像字段，也不尝试修改现有飞书应用。自动设置头像需要独立设计，
前提是先确认官方接口与权限模型。

### macOS

`assets/macos/AppIcon.iconset` 保存 macOS 要求的 16、32、128、256、512 和
1024px 槽位。每个槽位使用对应的响应式版本，而不是只保存一张大图。

macOS 构建在现有 Apple runner 上调用系统 `iconutil` 生成
`Contents/Resources/HomeAgent.icns`。`Info.plist.template` 声明：

```xml
<key>CFBundleIconFile</key>
<string>HomeAgent</string>
```

构建同时把飞书 PNG 复制到
`Contents/Resources/brand/homeagent-feishu-avatar-512.png`。构建计划和 bundle
smoke check 把 `.icns` 与飞书 PNG 都视为必需输出。图标资产缺失、`iconutil`
失败或 plist 未引用图标时，构建必须失败，不能静默产出默认图标的 App。

## 触点替换

### 管理后台

`packages/web/src/layout.ts` 的 `🧠 homeagent` 替换为深色背景品牌锁定：
暖奶油屋檐、火种金和小写字标。导航仍保持现有尺寸与信息架构，不借机重做
页面。

### 首次设置

`packages/web/src/setup-view.ts` 的 `⌁ homeagent` 替换为扁平品牌标志和小写
字标。设置页现有米色、苔绿和阳光色背景可以保留；品牌陶土只用于标志与必要
强调，不要求整页换色。

### macOS 与发布

Finder、Dock、应用选择器和 DMG 中的 `HomeAgent.app` 使用新的 `.icns`。
发布文件名、签名、notarization、bundle identifier 和 URL scheme 均不变。

### 飞书

新的飞书应用继续使用 `HomeAgent` 名称。自动创建完成后，页面向管理员展示
标准头像下载和手动上传说明。已存在的应用不被自动更改。

## 数据流与兼容性

品牌资产不读取或写入用户配置：

```text
规范 SVG
  ├─ Web text import ──> 共享品牌组件 ──> 后台与设置页
  ├─ 响应式 PNG ──> AppIcon.iconset ──> iconutil ──> HomeAgent.icns
  └─ 512px PNG ──> Resources/brand ──> 固定本地下载路由 ──> 管理员手动上传飞书
```

没有配置迁移、数据迁移、数据库变更或机器人身份替换。更新应用后，用户现有
空间、任务、知识、凭据和飞书绑定保持不变。

## 错误处理

- SVG 校验失败时，测试和发布预检失败。
- 任一 macOS iconset 槽位缺失、尺寸错误或无法生成 `.icns` 时，macOS 构建
  失败。
- Web 品牌资源不得使用失败后回退到 emoji 的逻辑；编译期导入失败应阻止构建。
- 飞书头像下载资源缺失时，Integrations 页面显示明确的本地资产错误，不展示
  一个无效下载链接，也不声称头像已经配置。
- 飞书不支持自动头像设置不是运行错误；页面应始终把它描述为管理员手动步骤。

## 测试与验收

### 自动测试

1. SVG 静态校验：
   - 固定 viewBox；
   - 不含 `script`、`foreignObject`、事件属性、外部引用或字体；
   - 颜色只能来自批准的品牌色。
2. PNG 资产校验：
   - 飞书头像为 512×512、PNG 格式；
   - iconset 每个文件尺寸与槽位名称匹配；
   - 所有派生资产存在且非空。
3. Web 渲染测试：
   - 管理后台和设置页都渲染共享品牌组件；
   - 品牌标志有正确的可访问语义；
   - `🧠` 和 `⌁` 不再出现在品牌区域；
   - 页面不引用外部图片或字体。
4. macOS 构建测试：
   - build plan 包含 `HomeAgent.icns` 与飞书 PNG；
   - `Info.plist` 引用 `HomeAgent`；
   - smoke check 缺少 `.icns` 或飞书 PNG 时失败；
   - codesign 仍覆盖完整 App bundle。
5. 飞书下载测试：
   - 下载响应是 `image/png`；
   - 文件名稳定；
   - 响应体尺寸与仓库规范资产一致。
   - 路由不读取请求提供的路径，注入资产缺失时返回明确错误。

### 人工视觉验收

- 在 16、24、32、48、128、512 和 1024px 检查轮廓、中心和边缘清晰度。
- 在白色、现有米色、炉灰墨和主陶土背景上检查对比度。
- 检查飞书圆形裁切、macOS Dock、Finder、设置向导和后台深色导航。
- 关闭颜色后仍能通过屋檐与火种识别标志。
- 确认小火星不会被误认为未读通知或运行状态。

## 完成标准

- 用户在所有 HomeAgent 自有触点看到同一个屋檐与智能火种标志。
- macOS 不再显示默认 App 图标。
- 后台和设置页不再使用 `🧠` 或 `⌁` 作为品牌标志。
- 飞书头像资产在圆形裁切下完整，并可从本地设置页下载。
- 所有自动测试通过，现有用户数据与飞书绑定无需迁移。
