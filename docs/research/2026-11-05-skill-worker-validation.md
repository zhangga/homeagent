# Skill 准备与后台响应验收（2026-11-05）

本次修复把生产消息入口、Task/WorkAction 准入、执行准备、Skills 管理页和 Agent 就绪检查中的目录遍历与散列移入 Worker。保持完整兼容目录、冻结 bundle 摘要、来源优先级、依赖文件和既有容量边界。

## 根因与实现

此前按需加载已经生效，但消息入队时的全目录冻结，以及执行上下文、调用开始和进程启动三个位置的同步目录校验仍占用主线程。此前本机复现中，首次扫描曾阻塞 HTTP 约 73.6 秒；文件缓存较热的另一轮也阻塞约 4 秒。

- `SkillCatalog` Worker 保存解析结果与文件身份记录。未变化时不重新遍历目录或散列内容；目录、依赖或来源变化时重新解析，并与该 Run 的冻结证据比较。并行 Run 持有各自的证据引用。
- 技能包 Worker 负责读取、散列、容量预留、复制和副本校验。首次加载完成后复用副本，保留 scripts、resources 和已安装的 `node_modules`。副本身份未变化时不再次读完整内容。
- 最后一次授权检查仍与进程创建处于同一同步执行段：本机授权、Task 的持久化批准、Workdir 身份和准备文件身份均保留；不缓存授权结果跨越异步等待。
- no-tools 调用直接记录技能禁用证据，避免为了不执行的技能遍历本地目录。
- macOS 构建与产物检查包含两个 Worker 入口；另有不依赖 macOS 的打包 Worker 启动测试。

## 完整链路测量

使用临时数据目录、真实 Orchestrator、真实 Engine、实际 Provider 子进程与技能加载脚本。模型程序和飞书投递使用离线替身，不调用真实模型、不发送真实飞书消息。另一个进程持续读取真实管理路由 `/work`、`/healthz`，防止服务端自身定时器被阻塞后低估延迟。

覆盖 3 条消息、6 次路由/生成调用：首次无技能请求、两条独立消息并行、重复加载同一技能、后续依赖加载、回复状态落盘以及结束清理。自动回归使用 116 个技能；另一次本机测量读取实际安装的 116 个技能，加入 2 个测试技能，并实际准备 `baoyu-post-to-wechat` 的完整冻结副本，没有执行其发布功能。

本机实际技能目录的一次测量如下。后两行时间窗口重叠，不能相加计算总请求数。

| 场景 | 整条离线链路耗时 | HTTP 样本数 | HTTP P95 | HTTP 最长 |
| --- | ---: | ---: | ---: | ---: |
| 首次建立完整冻结目录，无技能加载 | 75.1 秒 | 9,510 | 2.7 毫秒 | 284 毫秒 |
| 并行的普通消息，无技能加载 | 2.4 秒 | 168 | 18.0 毫秒 | 138 毫秒 |
| 加载现有较大技能及测试依赖 | 20.1 秒 | 2,238 | 3.9 毫秒 | 263 毫秒 |

3 条 Run 均成功且投递状态为 `sent`；两条独立消息的运行区间重叠；Worker 全目录扫描计数为 **1**，目录解析版本保持不变；重复技能请求返回同一份副本，结束后全部清理。没有重现此前数秒至数十秒的 HTTP 扫描阻塞。

**限制：首次完整校验的磁盘耗时仍然存在。** 这次把它移出了 HTTP 主线程，并复用校验结果，没有通过减少技能或取消冻结校验来掩盖耗时。离线链路耗时包含测试程序、脚本启动与文件准备，不能作为真实模型的回复时延承诺。真实运行中的其它磁盘、数据库或渲染负载也可能影响后台响应。

## 回归入口

```sh
bun test packages/app/src/skill-preparation.test.ts
bun test packages/core/src/skill-catalog-worker.test.ts packages/core/src/engine-execution-permits.test.ts
bun test packages/llm/src/provider-skill-session.test.ts packages/llm/src/providers.test.ts
bun test scripts/skill-worker-bundle.test.ts scripts/build-macos-app.test.ts scripts/smoke-macos-bundle.test.ts
bun run typecheck
```

链路回归同时断言 Worker 全目录扫描次数为 1、两条独立消息确实重叠执行、技能依赖可读、重复加载复用副本、终态和清理正确。文件变更、目录成员变化、准备期间修改技能、撤销授权、替换 Workdir、可写任务批准、取消、超时、重试和恢复由相邻测试覆盖。

最后复查补充了副本根目录的身份回归：在两次按需加载之间替换外层目录，即使技能内容没有变化，后续模型调用仍必须在启动前失败。发布新技能只更新目录的内容变化记录，不接受新的根目录身份，并保留规范路径校验。该测试先复现了缺失校验时的错误放行，再验证修复。

Windows Bun 1.3.14 的 `expect(promise).rejects` 在复用 Worker 回包场景下可能卡住；相关回归先等待 Promise 完成，再检查同一个错误，不改变生产行为。异步准备后的取消与重复任务测试等待实际 Provider 启动信号，不再假设在调用栈返回前模型已启动。
