# 聊天目标生成工作计划：开发与验收记录

日期：2026-11-05。范围：明确的多步骤聊天目标生成持久工作计划，接入已有 WorkAction / Task Run 续作。

## 已实现的行为

1. 聊天中发送「整理本周项目进展，找出阻塞项，生成周报」或「我想先收集本周的项目进展，然后整理并生成周报」，创建独立事项并生成有顺序、带完成标准的步骤。
2. 工作台保留完整 Runbook 和剩余步骤；规划指令、Agent 指令、Provider、模型和时限随本轮冻结。规划调用不携带执行工具和 Provider 会话历史。
3. 计划回执成功送达后开启续作，立即唤醒首个动作。后续按现有 60 秒调度检查领取下一步；每个事项每轮最多一步，同事项串行，其他事项的慢步骤不阻止独立事项继续推进。启动恢复先安装调度循环，再后台推进恢复动作，不等待慢动作结束后才完成启动。
4. 后续步骤读取完整的已验收执行报告，避免仅依赖 200 字进度摘要。最后一步验收后自动完成事项；成果优先回复原聊天消息，沿用群回复模式，私聊不强制话题回复，使用现有 Task 通知幂等键和持久重试。新规划显示本轮模型配置；复用已保存计划的重试明确标注本次未调用模型。
5. 只读执行报告满足原有条件时自动验收；可写、完全访问继续使用逐次执行审批与人工结果验收。完全访问 Task 仍需原有本机执行确认，证据在接受前保持 `held`。
6. 保留普通问答和单项请求路径。「只要方案，不要执行」不启动工作动作；模型也可返回普通回答决定。单项「分析独立接口检查」不会因包含多个动作词而误入计划流程。

## 持久性与兼容性

- WorkItems v2 新增可选 `chatPlanRunId`；完整计划和待执行边界继续由 `runbook` / `nextActions` 保存。
- WorkDispatch v1 的新增 `work-plan` 响应保留目标与冻结规划指令。新版本读取旧数据；包含新响应类别的数据不应直接交给旧版本消息消费者处理。
- 计划写入、Run 成功提交和回执送达分别使用已有持久边界。中途失败不会自动执行；重试复用已经保存的计划，不能重新放回已消费的步骤。
- 重启可以恢复尚未执行的排队规划；已运行的中断进程不重放。已经关闭的续作策略不被恢复逻辑重新开启。
- 计划开启后独立于有界 Chat 历史；本机持久输入保留投递来源。Space v21 保留计划、来源历史标识和原有续作策略，不携带本机投递来源，不从导入历史重新开启已关闭策略；恢复后的通知沿用现有 Space 绑定投递。

## 隔离 HTTP 验收

Windows 上启动独立临时数据目录、替身 Provider / Connector 和随机本机端口，通过真实 HTTP 请求读取工作台。
首个动作等待替身 Provider 返回时，`/work` 返回 200，耗时 13 ms；事项详情返回 200，耗时 1 ms，包含计划与完成标准。
释放首步后，第二步完成；事项状态为 `completed`，剩余步骤为 0，计划回执与两步成果共 3 条回复，最终成果回复原消息。
这是一次隔离检查的观测值，不代表真实 Provider 或飞书的耗时承诺。临时服务、数据和一次性检查脚本已清理。

## 使用现有运行环境验收

1. 重启 HomeAgent 加载新代码，在已连接的测试群 @助理发送上述周报目标，核对工作台内完整步骤及完成标准。
2. 观察首步自动启动或进入原有审批。完全访问 Agent 须按原有配置开启 Task 本机确认，再按每个 Run 的审批与结果验收推进。
3. 回复原消息「进度」「暂停」「恢复」，确认事项定位正确、暂停期间不领取新步骤。另发一个独立多步骤目标，确认两个事项可各自推进。
4. 等待全部步骤通过验收，检查原话题成果与事项完成状态；需要停止时回复原消息「取消」。

本次使用隔离临时数据和替身模型/传输，没有修改实际 HomeAgent 数据、调用真实 Provider 或发送真实飞书消息。
